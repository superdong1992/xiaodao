# 共享边界与输入

CCCC 是 RPC 模块，BBBB 是其上一级进程间消息通信机制。日志模板中的 `{字段名}`、`%s`、`%u`
是运行时字段值的占位符，不属于日志原文。

同步调用超时返回 `CCCC_STATUS_S`，其中 `bRpcSuccess=false`、`uiErrno=0xaaaaaaaa
CCCC_ERRNO_REQUEST_TIMEOUT_FAIL`；异步调用超时则调用用户注册回调，首个入参内容相同。超时
表示客户端在截止时间前没有收到包含 API 执行结果的响应；服务端可能已经执行 API。超时不等于
取消，后续执行仍可能产生副作用。

BBBB 默认有进程级日志抑制：同一进程内，75 秒内已经打印过同一源码行且错误码相同的日志，
后续同一源码行、同一错误码不再打印。抑制只看进程、源码行和错误码，不看字段值、请求 ID 或
线程；字段不同也不会重新打印。除非日志明确说明“无抑制”，Wiki 中的 BBBB 日志都受此规则
影响。

客户端超时模板是：

```text
rpc call %s:%s timeout limit %u recv no response
%s rpc %s call unsuccess, reqid(%u), timeout %u
```

前者字段依次为服务名、API 名、超时时间（毫秒）；后者依次为服务名、API 名、进程内唯一请求
ID、超时时间（毫秒）。这些模板确认超时及请求关联，但本身不能区分三种原因。

日志缺失只能形成未知边界：75 秒抑制、同进程 180 秒一次的排队历史限流以及死循环日志的
条件打印都会使证据不可见。没有 `DEADLOOP_DETECTED` 不代表没有死循环；没有排队历史不代表
没有排队。生成结果应逐项说明已确认的正向证据和仍未知的部分。
