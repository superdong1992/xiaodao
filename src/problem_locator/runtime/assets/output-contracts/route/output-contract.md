# ROUTE 输出合同

最终响应只返回简短 JSON 对象，提供 `skill_id` 和 `reason`；不要求生成置信度分数。

```json
{"skill_id":"diagnosis-skill/example","reason":"当前问题是该 Skill 覆盖的跨进程 RPC 超时。"}
```

`skill_id` 必须逐字取自本次 `SKILL_INDEX` 中的 `skill_id`，或为 `null`。`reason` 用一句话简短说明决定性的范围依据（最多 1024 字符）。兼容可选 `confidence`，但它只是模型自评分，不是统计概率，也不参与准入。

目录为 schema_version 1，包含最多 5 个候选。每项提供 `skill_id`、`name`、`capability`、`summary`、`routing`。完整阅读各候选的适用条件和排除条件，以 `CONTEXT_SNAPSHOT` 中的本次事实判断，不能把召回顺序当作结论。无法确定唯一适用的候选时返回 `skill_id: null`，不要选择“最接近”的一个。

不要输出逐项审核结果、条件理由或证据引用。按适用条件原文理解组合关系；当前事实明确命中排除条件时不选，未提及排除情形不等于命中。`non_goals` 不属于本次定位目标。缺少后续诊断材料不等于适用范围不符，也不要求先证明根因；只有用于区分适用范围的信息不足时，才据此转通用。

以上是模型应返回的标准格式。服务端以 `skill_id` 决定路由；理由仅用于展示，省略时提供普通说明。可选置信度接受数字字符串，缺省或无法使用时在现有字段保存为 0，不影响有效候选的选择；0 不表示测得的正确率。空响应、没有选择、候选外 Skill、无法解析的 JSON 均正常转通用，不记录格式异常、不重新调用路由模型。额外字段忽略，正常路由审计保留，版本、哈希和任务身份由服务端绑定。

所有路由输入均已提供。不要调用文件工具，不要创建草稿，不要输出 Markdown 代码块或 JSON 之外的内容。
