# 专用 Skill 的路由准入

ROUTE 先检查已有精准关键词直达规则；未直达时，本地召回最多 5 个相关 Skill，再调用一次模型。模型阅读这些候选的完整适用条件和排除条件，只返回 `skill_id`、简短 `reason` 和 `confidence`。服务端将本次候选中的选择映射到 Job 固定的 Skill 版本，置信度不低于 0.95 时进入专用流程。置信度是附加门槛，不代表经过统计校准的正确率。

模型无法明确选择时返回 null；低置信度、空响应、无法解析或候选外选择都按 `NO_CAPABILITY` 转入通用定位。只有一个候选也由模型判断，不因本地词语命中自动选用。已明确适用但缺少日志、时间或进程参数时，仍进入专用流程，再补齐材料。不得把“诊断材料未齐”写成排除条件。

不再要求模型回写 `assessments`、逐条理由或引文，服务端也不再按这些字段审核。额外字段（包括历史 `assessments`）忽略，不因其缺失、重复或格式差异中断诊断。

根字段按可用内容读取：数字字符串形式的置信度正常采用；缺失或无法使用的置信度按 0 处理；理由为空时采用普通说明，超长理由只保留输出字段允许的长度。上述正常回退不记录格式异常、不重试模型。冻结目录和任务版本一致性检查不变，取消、超时和服务故障沿用原处理方式。

## 本地候选召回

检索输入来自本次 Job 固定的问题描述和活跃的用户事实、已确认事实；再次路由使用最新快照，不沿用首轮原文或历史结论。索引使用 Skill 名称、能力名称、简介、适用条件和已有 `direct_match_keywords`，排除条件和材料清单不参与加分。精准直达规则保持独立，召回命中本身不能跳过模型。

英文忽略大小写，保留完整标识符和分段，支持 `IO`、`DB` 等短组件名；中文使用连续二字片段，过滤常见请求词和故障泛词。排序先看明确关键词命中数，再按词语重合评分：名称和能力权重 3、适用条件权重 2、简介权重 1。同词跨字段取最高权重，重复出现不累加；稀有词权重为 `1 + ln((N + 1) / (df + 1))`，其中 N 是可召回 Skill 数，df 是包含该词的 Skill 数。同分按 Skill ID 排序。

只取有命中的前 5 个，不凑数、不因第 5、6 名同分扩容；完全无命中则直接通用，零路由模型调用。模型索引只含本次候选的 ID、名称、能力、简介和完整适用／排除条件，不包含版本哈希或材料要求。服务端保留完整目录。未入选表示“未召回”，不能声称已排除；同义表达或第 6 名候选仍可能漏选。

## 注册与升级

Methods 注册使用 `registration-template.json` 的 `schema_version: 2`，文档型注册使用 `schema_version: 3`；两者都必须声明 `routing`：

```json
"routing": {
  "applicability": [
    {"id": "rpc-timeout", "description": "问题是客户端 RPC 调用超时，需要定位超时原因。"}
  ],
  "exclusions": []
}
```

适用条件为 1～16 条，排除条件为 0～16 条。每条仅含 `id` 和 `description`；ID 为不超过 64 字符的小写 kebab-case，在同一 routing 中唯一；说明为不超过 1024 字符的非空文本。条件应来自原始 Wiki，明确领域、场景和症状。没有已声明的额外排除条件时写空数组，不补写经验规则。

旧 `schema_version: 1` 注册仍可加载和读取历史记录，服务端完整索引中的 `routing` 为 null，不参与召回。生产目录仍固定在 Job 中，不按初始事实名过滤；Runtime 再按当前内容筛选模型候选。全部候选都缺少范围声明时直接转通用，零模型调用。声明纳入注册内容哈希，已固定的 Job 不使用运行中被替换的声明。

第二个创建器 `wiki-to-logparse-diagnosis-skill` 默认生成 v3 注册，支持 Wiki 和已有文档型 Skill；第一个 `wiki-to-diagnosis-skill` 继续只生成 Methods 包。v3 的材料要求和 `logparse/direct_files/none` 准备方式不改变路由判断，参数与材料缺失在选定 Skill 后处理。MCP 的七个公开输入、Case REST 输入和持久化 `RouteDecision` 格式不变。

更新时先在 `SKILL_DIR` 外生成并校验独立目录。结束活跃任务后切换并重启，不让同一能力的新旧版本同时参与路由。本次内置版本为 Router `3.0.0`、路由输出合同 `7.0.0`、路由上下文策略 `2.0.0`；升级后新建任务，不回放旧合同。公开 MCP、REST、Job 和 `RouteDecision` 不变，无数据库迁移，不改写历史报告或审计。

## 审核与排查

三字段输出格式见[ROUTE 输出合同](../src/problem_locator/runtime/assets/output-contracts/route/output-contract.md)。模型以当前问题和事实判断候选，不把 Skill 说明、假设或历史结论当作当前问题的事实；多个候选无法区分时返回 null，不要求回写推理过程。

可编码的模型原文保存为 `route-response.raw.txt`。正常决策保存 `route-admission.json`，新策略为 `shortlisted_route_v1`，其中 `retrieval` 记录 `lexical_top5_v1`、候选评分、实际入选 ID 及完整目录、上下文和模型索引的哈希。零召回保存 `model_called: false`；未入选项只标记为未召回。事件 `runtime.route.admission` 仍仅记录关联标识、选择和原因代码，不生成格式异常记录。审计写入失败时任务中断；旧审核和恢复记录继续保留，不改写历史字节。

候选范围与置信度门槛不受 `METHODS_EVIDENCE_VALIDATION` 或 Reviewer 开关影响。确定性测试验证候选上限、输入内容、调用次数和状态转换；它不能证明公司模型的重复生成已消除。真实模型测试前须审阅对应 `--plan-only` 的身份、场景、调用数和预算，再用原故障问题对比循环情况、路由结果、输出 token 和耗时。
