# 诊断交付策略

网站实际调用路径是网站后端 → Agent HTTP API → 共享应用服务 → 调度器 → Runtime → 报告与归档。MCP 是同一应用服务的另一个入口。以下策略同时适用于 Web 和 MCP 发起的 Methods 诊断。

## 当前默认行为

`METHODS_EVIDENCE_VALIDATION=advisory` 在服务启动时固定。引用文字、行号、marker、身份词不一致、引用缺失、方法标识不匹配，以及同一身份下出现不同结论，都不再成为清空整份诊断的理由。完全相同的发现合并。格式正确但没有发现时交付 INCONCLUSIVE；有可识别模型发现时交付 PARTIAL，并明确说明未执行证据一致性复核。

报告不把模型判断写成已验证结论：`root_cause=null`，没有依据的完成条件为 UNKNOWN，校验状态为 SEMANTIC_ONLY。引用位置只从本次实际冻结的日志解析；无法定位时仅关联本次输入日志，不编造行号或引用原文。未知方法标识保留为待核对说明，不代表该方法已在 Skill 中匹配。

原始响应、有效结果、处理回执分别写入私有诊断审计，回执记录位置、原因、哈希和 `diagnostic_id`。公开页面不展示原始异常和内部路径。既有报告字节保持原样。

设置 `METHODS_EVIDENCE_VALIDATION=strict` 可恢复原核验；需重启服务，切换前先结束活跃诊断。strict 下关闭 Reviewer 时逐项保留可核验发现，开启时执行整份核验。Reviewer 开关独立于该设置，开启后仍只审核一次整份结果；审核继承对应诊断审计中记录的证据策略，历史审计缺少该字段时视为 strict。

## 输入和资源边界

Intake 先保留有效参数，再按剩余要求追问。用户引用可以包含原值两侧的上下文；完全重复项合并，多余字段和单项格式错误不会丢掉其他字段。明确带时区的完整 ISO 时间可规范为毫秒 UTC，标识符不改写、缺失时区不猜测。更正已冻结事实仍需新建任务。每条新消息最多一次 Intake，不增加修复模型调用。

公开 API 和七个 MCP 工具的输入类型及扁平 schema 不变。非法 JSON、不可识别的顶层结果、多个终态、进程异常退出、输出超限、权限错误、文件归属错误、路径越界和实际字节/哈希变化仍拒绝。advisory 不绕过文件安全，也不把未取得的日志加入归档。

## 性能改动和验证范围

advisory 去掉模型执行后的第二次 marker 全量扫描。报告与归档逐份日志提取本次引用需要的内容，随即释放完整拆行列表；单次构造内复用相同行和范围摘要。跨调用重新校验，避免缓存掩盖文件变化，也不长期保留全部日志的拆行副本。后台 ZIP 写入继续按实际流计算 SHA-256。

网站从同一 Case 快照读取产物元数据，省去独立产物列表请求及重复列表匹配。小于报告上限的报告在有界内存中校验后展示，ZIP 继续使用文件流。下载始终以配置地址、授权 Case 和核验过的产物 ID 寻址，不信任产物响应里的下载 URL。

验收使用 Dev affected + full deterministic 的合成场景和操作计数，不调用真实模型。计数降低只证明相应重复工作已消除，不代表公司内网端到端延迟或真实模型完成率已得到验证。
