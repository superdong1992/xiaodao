# 8.0 到 8.1：保留历史数据的离线升级

本工具只支持 `v11-contract-r1` → `v11-contract-r2`，State schema 保持 11。新版服务不会自动改写旧目录；不要只修改 `data-format.json`，已完成任务的数据库快照也绑定合同修订。

## 升级前

在旧版本停止接收新任务，完成或结束活跃诊断，并排空上传、派发和归档写入，然后停服。活动 Case 只保存在内存，升级工具无法恢复未完成的诊断。准备包含 SQLite 主库、WAL 和资源文件的完整备份，并保留旧版程序与配置。

在 Linux Server 使用 8.1.0 的运行环境执行以下命令。源目录必须是已初始化的 r1 目录；目标目录必须尚不存在，且不能与源目录相同或互相包含。两个目录应位于受控的本地文件系统，并预留足够空间容纳完整副本。

```bash
problem-locator-data-upgrade \
  --source-root /srv/xiaodao/data-r1 \
  --target-root /srv/xiaodao/data-r2 \
  --plan-only
```

`--plan-only` 核对目录、版本、现有实例锁及文件清单，不调用模型，不打开源 SQLite 数据库。它不代表数据库和资源闭包已经验证通过；这些检查在执行时针对独立副本完成。

## 执行与切换

确认计划后，在服务保持停止的状态下执行：

```bash
problem-locator-data-upgrade \
  --source-root /srv/xiaodao/data-r1 \
  --target-root /srv/xiaodao/data-r2 \
  --execute
```

工具锁住源实例，复制包括 WAL 在内的完整数据，只在暂存副本中处理数据库。迁移更新目录标记、每条已完成任务快照的顶层合同修订，以及核验后的附件内部路径。历史会话、事件序号、幂等记录、资源索引、归档任务和不可变报告、日志、审计文件保持一致。

空闲且没有待处理工作的会话可以保留。已经关闭的失败或中断会话，也可以保留原先的内存 Case/Job 标识和未完成派发、附件记录；这些历史记录不会被恢复执行。有报告的历史仍须核对持久 Case、产物引用和文件哈希。

校验直接读取副本中的数据库与资源，不启动服务，不执行恢复流程，也不调用模型。数据库完整性、任务快照、引用和资源哈希全部通过后，工具才发布目标目录并输出升级凭据。原始模型响应、报告和审计产物中的旧版本信息不作全文替换。

执行成功后，保存目标目录中的 `data-upgrade.receipt.json` 和命令输出，将服务配置的 `DATA_ROOT` 显式切到目标目录，再用 8.1.0 启动。检查 `/ready` 和 `/openapi.json`，确认版本为 8.1.0；读取历史会话，下载已知报告并核对原哈希。这些检查不要求发起新诊断。

## 失败与回退

锁冲突、损坏数据、复制中断或校验失败都不得留下可启用的目标目录，源目录保持完整。暂存副本携带未完成标记，新版服务会拒绝打开；它只用于排查，不要删除标记后强行启动，也不要自动删除暂存副本或原目录。

切换后尚未产生新业务数据时，可停服并恢复旧程序和旧 `DATA_ROOT`。新版已经接收任务后，旧目录不包含这些新记录，不能把回切当作数据合并；本工具不提供 r2 → r1 反向迁移。

旧 `StateExport`、审计文件和导出包保留原始字节，但本次升级不提供旧导出文件在新版中的直接导入或 replay 兼容。V1–V10 数据也不在本工具支持范围内。
