# 升级到 8.2：保留历史数据与会话归属

8.2.0 使用 Agent 会话存储格式 v2（Agent storage v2）。升级工具会复制旧数据，再在副本上升级，支持的来源是 8.0 的 `v11-contract-r1` 和 8.1 的 `v11-contract-r2`。State schema 仍为 11，协议修订号为 `v11-contract-r2`，报告 schema 仍为 3。

数据目录的版本标记新增 `agent_storage_version: 2`，SQLite 元数据也会记录版本。新版服务不能直接打开旧目录，旧服务也不能打开新目录。不要手工替换版本标记。

## 升级前

先让旧版服务停止接收新任务，等待正在执行的诊断完成，或主动结束这些诊断。确认上传、任务派发和归档写入都已结束后，再停止服务。正在处理的 Case 只保存在内存中，升级工具无法恢复未完成的诊断。请准备包含 SQLite 主库、WAL 和资源文件的完整备份，并保留旧版程序与配置。

在 Linux 服务端的 8.2.0 运行环境中执行以下命令。源目录必须是已初始化、尚未升级到 Agent storage v2 的 r1 或 r2 数据目录。目标目录必须尚不存在，不能与源目录相同，也不能互相包含。两个目录都应位于管理员维护的本地文件系统，并预留足够空间保存完整副本。

```bash
problem-locator-data-upgrade \
  --source-root /srv/xiaodao/data-old \
  --target-root /srv/xiaodao/data-8.2 \
  --plan-only
```

`--plan-only` 只核对目录、版本、现有实例锁和文件清单，不调用模型，也不打开源 SQLite 数据库。数据库及其引用资源的完整性检查，会在实际升级时针对独立副本执行。

## 导入网站会话归属

网站需要从现有数据库导出会话与用户的对应关系，保存为以 `conversation_id` 为键、`owner_key` 为值的 JSON 对象。在查看计划和执行升级时，都可以用 `--ownership-map /srv/xiaodao/owners.json` 指定该文件。`owner_key` 必须与新版网站后端根据登录用户生成的值完全一致，格式为 64 位小写十六进制字符串。不要直接使用用户名，也不要接受浏览器自行指定的用户标识。

```json
{
  "10000000-0000-0000-0000-000000000001": "a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0"
}
```

映射文件可以只包含已确认所属用户的会话。未提供映射的历史会话会保留，但不会出现在任何用户的会话列表中，网站也不能自动将其分配给用户。上线前应整理好已知的会话与用户对应关系；不要从旧请求 ID 的哈希反推用户。重复键、格式错误或不存在的会话都会导致升级失败。升级记录只包含映射文件的 SHA-256 和记录数量，不输出具体的 `owner_key` 值。

## 执行与切换

确认计划后，在服务保持停止的状态下执行：

```bash
problem-locator-data-upgrade \
  --source-root /srv/xiaodao/data-old \
  --target-root /srv/xiaodao/data-8.2 \
  --ownership-map /srv/xiaodao/owners.json \
  --execute
```

没有会话归属映射时，省略 `--ownership-map`。工具会锁定源实例，复制包括 WAL 在内的完整数据，并且只修改暂存副本中的数据库。升级会新增会话列表、诊断轮次等表和索引，为每条旧会话建立一个历史轮次，并转换已核验的附件内部路径。r1 快照只更新顶层协议修订号；r2 快照保留原始字节。历史消息、事件、回执的原始字节和事件序号不变，报告、日志和审计文件也不改写。

空闲且没有待处理工作的会话可以保留。已关闭的失败或中断会话，也可以保留原先内存中的 Case/Job 标识，以及未完成的派发和附件记录；这些历史记录不会触发任务重新执行。对于已有报告的会话，工具仍会核对已保存的 Case、报告和其他产物的引用，以及文件哈希。

旧版参数整理阶段使用随机工作区 ID。升级工具会核对服务端整理记录中的会话 ID、工作区 ID，以及原始响应和最终采用响应的大小、SHA-256。全部吻合后，才会记录工作区属于哪个会话，供以后删除会话时清理。无法可靠确认所属会话的旧工作区会保持原样，继续按原有工作区保留策略清理，不会因猜测归属而随某个会话删除。

校验时，工具直接读取副本中的数据库和资源，不启动服务、不恢复任务，也不调用模型。数据库完整性、任务快照、引用关系和资源哈希全部通过检查后，才会生成可用的目标目录并输出升级记录。原始模型响应、报告和审计文件中的旧版本信息会保留，不作全文替换。

执行成功后，保存目标目录中的 `data-upgrade.agent-v2.receipt.json` 和命令输出。此前 r1→r2 升级留下的 `data-upgrade.receipt.json` 会原样保留。将服务配置中的 `DATA_ROOT` 改为目标目录，再启动 8.2.0。检查 `/ready` 和 `/openapi.json`，确认版本为 8.2.0；以已有会话归属记录的用户身份读取历史会话，下载已知报告并核对原哈希。这些检查无需发起新诊断。

## 失败与回退

发生锁冲突、数据损坏、复制中断或校验失败时，工具不会留下可启用的目标目录，源目录仍保持完整。暂存副本带有未完成标记，新版服务会拒绝打开，只能用来排查问题。不要删除标记后强行启动，也不要自动删除暂存副本或原目录。

如果切换后尚未产生新业务数据，可以停服并恢复旧程序和旧 `DATA_ROOT`。如果新版已经接收任务，旧目录中不会包含这些新记录，回退也不会自动合并数据。本工具不支持 Agent storage v2→v1 或 r2→r1 的反向迁移。

旧 `StateExport`、审计文件和导出包保留原始字节。本次升级不支持将这些旧导出文件直接导入新版，或在新版中重放。本工具也不支持 V1–V10 数据。
