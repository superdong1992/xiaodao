# 升级到 8.2：保留历史数据与会话归属

8.2.0 使用 Agent storage v2，支持从 8.0 的 `v11-contract-r1` 或 8.1 的 `v11-contract-r2` 旧会话存储复制升级。State schema 仍为 11，合同修订为 `v11-contract-r2`，报告 schema 仍为 3。目录标记新增 `agent_storage_version: 2`，SQLite 元数据同时记录版本；新版服务拒绝直接打开旧目录，旧服务也无法打开新目录。不要手工替换版本标记。

## 升级前

在旧版本停止接收新任务，完成或结束活跃诊断，并排空上传、派发和归档写入，然后停服。活动 Case 只保存在内存，升级工具无法恢复未完成的诊断。准备包含 SQLite 主库、WAL 和资源文件的完整备份，并保留旧版程序与配置。

在 Linux Server 使用 8.2.0 的运行环境执行以下命令。源目录必须是已初始化、尚未升级 Agent storage v2 的 r1 或 r2 目录；目标目录必须尚不存在，且不能与源目录相同或互相包含。两个目录应位于受控的本地文件系统，并预留足够空间容纳完整副本。

```bash
problem-locator-data-upgrade \
  --source-root /srv/xiaodao/data-old \
  --target-root /srv/xiaodao/data-8.2 \
  --plan-only
```

`--plan-only` 核对目录、版本、现有实例锁及文件清单，不调用模型，不打开源 SQLite 数据库。它不代表数据库和资源闭包已经验证通过；这些检查在执行时针对独立副本完成。

## 导入网站会话归属

网站从现有归属数据库导出 `conversation_id` 到 `owner_key` 的 JSON 对象，可用 `--ownership-map /srv/xiaodao/owners.json` 同时传给计划和执行命令。`owner_key` 必须与新版网站后端根据认证用户生成的值完全一致，为 64 位小写十六进制字符串；不要使用用户名，也不要接受浏览器自报的归属。

```json
{
  "10000000-0000-0000-0000-000000000001": "a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0"
}
```

映射可以只包含已确认的记录。未提供映射的历史会话会保留，但不会出现在任何用户的目录中，也不能被网站自动认领。上线前应完成已知历史归属的映射；不要从旧请求 ID 的哈希反推用户。重复键、格式错误或不存在的会话会使升级失败。升级凭据只记录映射文件的 SHA-256 和数量，不回显归属值。

## 执行与切换

确认计划后，在服务保持停止的状态下执行：

```bash
problem-locator-data-upgrade \
  --source-root /srv/xiaodao/data-old \
  --target-root /srv/xiaodao/data-8.2 \
  --ownership-map /srv/xiaodao/owners.json \
  --execute
```

没有归属映射时省略 `--ownership-map`。工具锁住源实例，复制包括 WAL 在内的完整数据，只在暂存副本中处理数据库。迁移新增会话目录、诊断轮次等表和索引，为每条旧会话建立一个历史轮次，并映射核验后的附件内部路径。r1 快照只更新顶层合同修订；r2 快照保留原始字节。历史消息、事件、回执的原始字节和事件序号不变，报告、日志、审计文件也不改写。

空闲且没有待处理工作的会话可以保留。已经关闭的失败或中断会话，也可以保留原先的内存 Case/Job 标识和未完成派发、附件记录；这些历史记录不会被恢复执行。有报告的历史仍须核对持久 Case、产物引用和文件哈希。

旧版问题整理阶段使用随机工作区 ID。升级只在服务端整理回执中的会话 ID、工作区 ID，以及原始和采用响应的大小、SHA-256 全部吻合时建立归属，供以后删除会话时清理。缺少可靠归属的旧工作区保持原样，仍按既有工作区保留策略清理；不会猜测归属后随某个会话删除。

校验直接读取副本中的数据库与资源，不启动服务，不执行恢复流程，也不调用模型。数据库完整性、任务快照、引用和资源哈希全部通过后，工具才发布目标目录并输出升级凭据。原始模型响应、报告和审计产物中的旧版本信息不作全文替换。

执行成功后，保存目标目录中的 `data-upgrade.agent-v2.receipt.json` 和命令输出。此前 r1→r2 升级留下的 `data-upgrade.receipt.json` 会原样保留。将服务配置的 `DATA_ROOT` 显式切到目标目录，再用 8.2.0 启动。检查 `/ready` 和 `/openapi.json`，确认版本为 8.2.0；使用已绑定的用户读取历史会话，下载已知报告并核对原哈希。这些检查不要求发起新诊断。

## 失败与回退

锁冲突、损坏数据、复制中断或校验失败都不得留下可启用的目标目录，源目录保持完整。暂存副本携带未完成标记，新版服务会拒绝打开；它只用于排查，不要删除标记后强行启动，也不要自动删除暂存副本或原目录。

切换后尚未产生新业务数据时，可停服并恢复旧程序和旧 `DATA_ROOT`。新版已经接收任务后，旧目录不包含这些新记录，不能把回切当作数据合并；本工具不提供 Agent storage v2→v1 或 r2→r1 反向迁移。

旧 `StateExport`、审计文件和导出包保留原始字节，但本次升级不提供旧导出文件在新版中的直接导入或 replay 兼容。V1–V10 数据也不在本工具支持范围内。
