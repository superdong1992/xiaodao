## 1. 通用定位上传和补交日志

请求顺序仍为预约附件、PUT 原始字节、发送消息引用附件。小刀前缀是 `/api/v1/agent`，网站示例前缀是 `/api/agent`。

首条问题有日志时，等待附件上传至 `READY`，再发送一条消息：

```json
{
  "request_id": "本次消息的稳定标识",
  "text": "用户的问题原文",
  "attachment_ids": ["已上传附件的小写规范 UUID"]
}
```

- 无日志仍可直接发送问题。通用定位不要求时间、槽位、进程或 PID。所有定位流程都应展示服务端 `current_questions`；通用流程也可能要求选择一份日志，不能把它误当作专用参数追问而隐藏。
- 通用定位一次采用一个归档。页面可直接限制单选；需要更换选择时，新消息只引用目标附件，不必重复上传。多包不能默认采用第一个。
- 首条消息或路由期间提交多个包，消息可能先被接受，再由通用预检在 `current_questions` / `assistant.question` 提示选一个；这与活跃 Generic Job 补包时同步返回的 `AGENT_LOG_SELECTION_INVALID` 是两条处理路径。
- 只发文字或发送 `attachment_ids=[]` 不会清除本轮已有附件选择。多包等待时，应明确发送只引用目标附件的新消息，不能用空列表取消选择。
- 运行中补日志仍使用同一个消息接口。服务端停止旧 Job，在**同一会话、同一轮次、同一 Case**重新分析。页面继续跟踪原 `run_id`，刷新当前 Job 和进度，不创建新会话或新轮次。
- 新包替换旧包，不自动合并。`text` 是补充描述，原问题保持不变。`READY` 只说明上传完成；消息接纳和附件采用需依据服务端收据、历史中的 `APPLIED` / `notice` 及最新快照。
- 关闭 SSE 不会停止任务。停止或删除仍走既有接口，不能用前端取消上传或断开订阅代替。
- 超时或可重试错误保留原 `request_id`、文本和附件列表；不得改 ID 无限重发，也不得重试时更换附件。

| HTTP / 错误码 | 页面处理 |
| --- | --- |
| `409 / AGENT_LOG_SELECTION_INVALID` | 提示只选一个归档，或先合包；改选择后用新消息 ID 提交 |
| `409 / AGENT_LOG_ALREADY_SELECTED` | 提示该日志已用于本次定位；不要自动重复重启 |
| `409` 或 `503 / AGENT_RESTART_PENDING`，`retryable=true` | 保留当前内容和待提交请求，稍后退避重试相同 ID 与内容；不将本轮判为失败 |
| `409 / AGENT_RUN_CHANGED` | 刷新快照并展示“本次定位已结束或发生变化”；此次补日志未被接受时，不显示为已采用 |
| `409 / AGENT_ATTACHMENT_NOT_READY` | 检查上传是否完成、附件是否属于当前会话；不能仅凭本地上传进度判定成功 |

服务端已经固定本次重启请求后，若旧报告抢先提交，补日志请求会明确拒绝，不发布对应的 `message.accepted`。如果请求进入服务端时本轮已经结束，则沿用既有消息规则：有文本的新请求会创建新轮，只有附件会因缺少问题文本返回 `400`。当前消息体没有 `expected_run_id`，页面必须核对收据中的 `run_id`，不能承诺所有结束竞态都返回 409。

页面已收到结束状态时，用户要用日志继续分析，应明确提交完整问题和附件开始新一轮。不能把旧轮已拒绝的请求自动改成新轮请求。

### 日志格式和报告提示

上传支持的压缩后缀仍为小写 `.zip`、`.tar`、`.tar.gz`、`.tgz`、`.gz`，归档支持不等于里面的任意格式都能解析。通用流程复用部署方安装的 Logparse，内部 `parse-only` 不调用依赖时间和进程的目标日志提取操作。

当前清单只接纳已校验的 Logparse `<task_id>/mech_modules/**/*.log` 文本产物，并记录相对路径、大小和 SHA-256。不能向用户宣称整个原包或任意纯文本格式都已分析。非默认产品由部署方设置 `GENERIC_LOGPARSE_PRODUCT`，前端无需增加产品输入框。

解析失败会明确报错。解析成功但清单为空时，本轮返回说明原因的 `UNRESOLVED` Markdown 报告；当前不会再调用通用 Skill 仅凭文字继续分析。**完全未提交日志**则继续走原有纯文本定位。页面应展示报告中的原因，允许用户重新选择受支持的日志或明确开始纯文本新轮次，不把 `UNRESOLVED` 隐藏成网络失败。

## 2. 赞踩按钮和历史报告

按当前展示报告的 `selected_run_id` 访问：

| 操作 | 相对网站前缀 `/api/agent` 的路径 |
| --- | --- |
| 读取资格与已有评价 | `GET /conversations/{conversation_id}/runs/{run_id}/feedback` |
| 提交评价 | `PUT /conversations/{conversation_id}/runs/{run_id}/feedback` |

PUT 请求仅包含 `request_id` 和 `rating`，后者为 `LIKE` 或 `DISLIKE`。成功响应沿用 `{ok,data,error}`，其中 `data.can_rate` 决定是否显示按钮，`data.rating` 决定选中状态。没有新增 SSE 反馈事件。

前端须串行提交同一报告的投票，提交期间禁用按钮。网络重试保持 ID 和内容；换票使用新 ID；再次点击已选按钮不表示取消评价。以服务端返回的最新状态为准，旧点赞重放可能返回最新的点踩。切换报告后不能用旧请求的迟到响应更新新报告。

默认 `GENERIC_MEMORY_ENABLED=false`，此时 `can_rate=false`；PUT 返回 `409 / AGENT_FEEDBACK_UNSUPPORTED`。专用定位即便也输出 Markdown，仍不适用通用报告反馈，不能按报告格式猜测资格。反馈失败不清除报告。

同步 [browser-client.js](../examples/website-agent/browser-client.js) 的 `conversations.getFeedback` / `setFeedback` 和 [server.mjs](../examples/website-agent/server.mjs) 的转发实现。具体错误、配额、归属与交互示例见[赞踩接入说明](generic-feedback-memory.md)。

## 3. 历史、附件和 SSE 过期

- 页面提示“诊断记录和附件保留 7 天，请及时下载”。旧轮次独立到期，刷新、改名和新开一轮不会续期。
- 历史记录、报告或附件已到期时，刷新目录与快照，清除失效入口；不要不断重试 404。会话被删或到期后，保留在浏览器中的 ID 也可能失效。
- 上传响应 `expires_at=null` 表示没有单独返回到期时间，不表示永不过期。未引用的预约附件满 7 天回收，仍被保留轮次引用的附件随引用保留。
- 收到 `409 / AGENT_EVENT_CURSOR_EXPIRED` 后，先 GET 会话快照，再将其 `last_event_id` 放入 `Last-Event-ID` 请求头续订。继续按事件 JSON 的 `sequence` 去重，不能反复使用旧游标。
- 普通 `EventSource` 无法读取失败响应的 JSON 或自定义该请求头。长期会话应使用支持状态码和游标恢复的流式 `fetch`，不能依赖无限自动重连。
- 创建请求幂等记录和删除凭据也有保留期。超期请求不自动重放；用户明确开始新诊断时使用新 ID。

完整时间起点、清理边界和部署注意事项见[保留策略](storage-retention.md)。

## 4. 下载和网站后端更新

若网站复制了旧版 BFF，应同步 `server.mjs`，包括公开错误码白名单、反馈路由、SSE 游标错误和下载生命周期。不要只更新浏览器 SDK。

报告与 ZIP 下载都应在浏览器断连时取消上游读取，设置总时限；仓库示例为 30 分钟。小报告仍先核验实际大小、SHA-256、类型和格式，再返回给浏览器；大包先暂存并校验，完成或失败后清理临时目录。下载失败只重试读取，不能触发重新诊断。反向代理时限需与网站部署要求一致。

## 5. 网站联调检查

1. 纯文字诊断和首条带一个日志包都可启动；通用流程不弹出时间、槽位、进程必填项。
2. 执行中补包仍是原轮次、原 Case；新包替换旧包，重复同请求不新增 Job；遇到重启交接等待时可用原请求重试。首条多包能展示选择追问，再用仅引用目标附件的新消息继续。
3. 旧报告抢先完成、停止和删除与补日志并发时，页面按收据和最新快照展示，不显示未接受的附件为已分析。
4. 多包、重复包、解析失败、空清单分别展示正确错误或 `UNRESOLVED` 原因。
5. 切换历史报告、赞踩换票、网络重试和功能关闭均符合资格及幂等规则；默认专用 Markdown 不显示通用赞踩按钮。
6. 旧事件游标能恢复快照后续订；过期报告和附件入口能失效；小报告与 ZIP 下载断连均取消上游。

8.2 早期的多轮状态、旧 `/status` / `/report` 入口删除和专用 Markdown 交付不是这两天新增的变化。尚未完成这些适配的网站，另按 [8.2 完整升级清单](website-agent-upgrade-8.2.md)补齐。
