# 通用定位经验库与网站赞踩接入

网站负责报告与每条追问旁的“有帮助 / 没帮助”按钮，小刀提供独立反馈接口、浏览器调用封装和后台经验处理。用户还可以在点踩后提交独立文字反馈，网站后端也可附带管理员分析资料；这条流程不经过追问接口。具体接入差异见[回答反馈与纠正适配说明](website-answer-feedback-upgrade.md)。本次不改页面布局，不新增取消评价、经验管理或提炼状态界面，也不新增 SSE 事件。

## 1. 接入路径和归属

调用关系仍为：浏览器 → 网站同源后端 → 小刀。网站后端透传现有登录 Cookie，小刀沿用 Redis 会话中的 `user.userid` 识别归属；浏览器不能指定用户归属。网站现有登录、Origin / CSRF 校验同样适用于提交评价。

| 操作 | 小刀服务路径 | 网站示例路径 |
| --- | --- | --- |
| 读取评价 | `GET /api/v1/agent/conversations/{conversation_id}/runs/{run_id}/feedback` | `GET /api/agent/conversations/{conversation_id}/runs/{run_id}/feedback` |
| 提交评价 | `PUT /api/v1/agent/conversations/{conversation_id}/runs/{run_id}/feedback` | `PUT /api/agent/conversations/{conversation_id}/runs/{run_id}/feedback` |

两个接口都不接受查询参数，GET 不接受请求体。路径标识必须是小写规范 UUID。查看历史报告时，使用报告的 `selected_run_id`，不要自动替换成当前轮次。

PUT 使用 `Content-Type: application/json`，只接受两个字段：

```json
{
  "request_id": "本次评价的唯一标识",
  "rating": "LIKE"
}
```

`request_id` 是 1 到 128 个 Unicode 字符的非空字符串，不能全为空白；`rating` 只接受 `LIKE` 和 `DISLIKE`。未定义字段会被拒绝。

GET 和 PUT 都返回现有的 `{ok,data,error}` 格式：

```json
{
  "ok": true,
  "data": {
    "schema_version": 1,
    "conversation_id": "10000000-0000-0000-0000-000000000001",
    "run_id": "50000000-0000-0000-0000-000000000001",
    "can_rate": true,
    "rating": "LIKE",
    "updated_at": "2026-09-21T12:00:00Z"
  },
  "error": null
}
```

尚未评价时，`rating` 和 `updated_at` 都是 `null`。已交付的 V2 Markdown 正式报告默认支持评价，包括通用定位和专用定位 `direct` 模式的报告；服务端核验用户归属、轮次和报告来源身份。旧 V1 报告和专用定位 `strict` / `advisory` 模式的结构化报告不支持评价，GET 返回 `can_rate=false`，PUT 返回 `409 / AGENT_FEEDBACK_UNSUPPORTED`。

`GENERIC_MEMORY_ENABLED` 只控制通用经验提炼和召回，不影响评价的读取和提交。通用原问题为空、超过提炼的 64 KiB 限制，或提炼任务容量已满，都不会取消评价资格。专用报告只保存评价，不生成或召回通用经验。

前端只读取当前用户、指定报告的评价，不返回投票总数、经验内容或其他用户的报告。

## 2. 浏览器调用与换票

复制更新后的 `examples/website-agent/browser-client.js`，同时保留同目录中的 `followup-contract.js`、`continuation-contract.js` 和 `feedback-comment-contract.js`；即使只接赞踩，也不能遗漏 SDK 静态导入的模块。沿用网站已有的 CSRF 设置：

```javascript
import { createAgentClient } from "/xiaodao/browser-client.js";

const client = createAgentClient({
  headers: () => ({ "X-CSRF-Token": readWebsiteCsrfToken() }),
});
const report = { conversationId, runId: conversation.selected_run_id };
const state = await client.conversations.getFeedback(report.conversationId, report.runId, {
  signal: new AbortController().signal,
});
// 根据 state.can_rate 显示按钮，根据 state.rating 显示选中状态。

// 将这份请求保存到本次提交状态中，失败重试时复用原对象。
const pendingVote = { request_id: crypto.randomUUID(), rating: "LIKE" };
const updated = await client.conversations.setFeedback(report.conversationId, report.runId, pendingVote);
// 仅当页面仍显示 report 中的会话和轮次时，用 updated 更新选中状态。
```

封装成功时返回解包后的 `data`，失败抛出 `AgentApiError`。它校验响应身份和字段，不自动生成请求 ID、不自动重试，也不缓存投票。

网站需落实以下规则：

- 只按反馈接口的 `can_rate` 显示按钮，不额外检查经验库配置、文本长度、Job 或 Skill，也不按 Markdown 格式猜测资格。
- 同一报告的提交串行处理；提交期间禁用两个按钮，或使用严格的单队列，避免并发换票改变操作顺序。
- 网络重试保留原 `request_id` 和 `rating`。同一 ID 改参数返回 `AGENT_IDEMPOTENCY_CONFLICT`。换票使用新 ID。
- 以服务端响应为准；旧点赞请求重放时可能返回最新的 `DISLIKE`，不能用旧请求内容覆盖它。
- 重复同票不会累计票数，也不会重复提炼经验。再次点击已选中的按钮不表示取消评价。
- 切换报告时取消旧的状态读取，并核对响应中的 `conversation_id`、`run_id`。不要把旧报告的迟到响应显示到新报告上。
- 读取和提交失败时保留已显示的报告。无法确认提交是否成功时，先查询反馈状态；如需重试，复用保存的请求。

| HTTP 状态 | 常见错误码或含义 | 网站处理 |
| --- | --- | --- |
| `400` | 参数无效 | 核对字段、标识和请求格式 |
| `401` / `403` | 网站登录或来源校验失败 | 沿用网站的登录和授权流程 |
| `404` | `AGENT_CONVERSATION_NOT_FOUND` / `AGENT_RUN_NOT_FOUND` | 会话、轮次不存在，已删除或不属于当前用户 |
| `409` | `AGENT_FEEDBACK_UNSUPPORTED` | 隐藏或禁用评价入口 |
| `409` | `AGENT_IDEMPOTENCY_CONFLICT` | 重试须使用原内容；新操作使用新 ID |
| `429` | `AGENT_FEEDBACK_LIMIT_EXCEEDED` | 反馈来源或请求 ID 配额已满，联系管理员；不自动重试 |
| `502` / `503` | 响应异常或服务暂不可用 | 保留报告与请求，提示稍后查询 |

`examples/website-agent/server.mjs` 是网站转发的唯一实现；`server.ts` 继续作为类型与启动入口。后端仅转发两个允许的输入字段，并核对上游响应身份，不把内部错误原文暴露给浏览器。

## 3. 后台经验闭环

报告和每条追问各有一份评价，按会话、轮次和回答标识隔离。报告反馈接口仍返回原有六个字段；追问反馈走独立路径，另含 `followup_id`。换票、刷新和旧请求重放只影响对应回答。评价本身不生成新的追问答案。

启用 `GENERIC_MEMORY_ENABLED` 后，首次为通用报告或普通追问点赞，会在保存反馈的同一事务中创建唯一提炼任务。普通追问提炼包含原问题、报告、此前追问与本条回答，明确只把本条获赞回答视为认可来源。后台产出一张脱敏经验卡，包含问题特征、适用条件、按优先级排列的排查步骤和限制；优先保留低成本、能区分原因的检查，而不是记住上一案的根因。

新增文字负反馈使用独立 `POST .../feedback/comments`，支持用户意见和网站后端附带的管理员分析资料；现有赞踩 GET/PUT 不变。请求约束、回执、网站资料快照与保留期限见[增量适配说明](website-answer-feedback-upgrade.md)。首次提交须已点踩，接收成功不代表经验已采纳，也不产生追问答案。

既有主动对话纠正仍兼容：用户用追问入口提交 `intent=CORRECTION` 和纠正文字。不填 `target_followup_id` 时，纠正该轮原报告；填写时只允许指定同轮已完成的追问。新回答会解释这次纠正，原报告、旧回答及下载字节保持不变。旧客户端省略新增字段，继续按普通追问处理。

纠正答案完成后，后台为这条答案安排一次证据核对与提炼，不要求用户再点赞。它读取现有只读日志快照，结合原报告、目标回答、用户纠正和新答案，判断纠正是否有来源证据支持。输出必须带快照内的文件、行号和摘录，服务端校验文件哈希、行号与摘录。只有接受纠正且引用校验通过，才发布共享经验；没有日志、工具不支持只读检索、证据不足或核对失败，都只保留当前会话中的纠正，不自动形成共享结论。给这类答案点赞也不能绕过核对。

每条答案最多安排一次后台任务。已接受的纠正会永久停用其明确替代的旧答案经验；旧任务晚到、旧答案再次获赞，都不能重新启用。纠正答案自己的点踩可停用新经验，原报告与新答案的票互不覆盖。点赞和来源日志中的支持证据都不等于本次问题已经解决，召回后仍须核实。

普通任务完成时重新检查该答案的最新投票；纠正任务检查其最新评价、替代关系和来源会话状态。失败保留反馈、不自动重试；重启恢复未开始任务，执行状态不确定的任务标记失败，不重复调用模型。后台处理与正常诊断分开，经验检索或提炼异常不应阻断正常诊断。

经验库仍按同一部署的 `DATA_ROOT + GENERIC_SKILL_NAME` 共享，只共享脱敏摘要，不开放原始问题、报告、追问或日志。专用定位的评价不生成或读取通用经验。没有点赞的历史普通报告与追问不自动学习；新提交的明确纠正按上述证据流程处理。

检索使用原问题和已收到的补充描述，按中英文关键词确定性匹配，每次最多采用一张、最多 4 KiB。完全相同的经验内容只在召回时去重，不合并来源记录或投票；某个来源被点踩、替代或删除，不影响其他仍有效的独立来源。超出上下文预算时整张跳过，不截断用户问题或日志指引。独立参考区包含来源类型、卡片标识、内容与哈希，随实际执行的 `context.txt` 保存。历史经验用于缩短排查路径，不能替代本次证据或覆盖 Skill 指令。

诊断速度优先：召回先用问题特征和适用条件筛选，再完整校验相关经验。每个检索实例最多缓存 256 份已校验的内容，不缓存投票、来源是否有效或上次选卡结果；每次仍读取当前有效来源，返回前再核对选中来源的状态和内容身份。卡片、来源或投票变化无需等待缓存到期。检索仍按卡量线性读取，不是全文索引，也没有固定耗时保证。必需上下文已耗尽或解析后没有可分析日志时，不执行无用的召回；现有上下文阶段记录召回耗时和是否实际加入参考区，不新增模型调用。

后台只在前台已观察到空闲时领取新的提炼或纠正核验任务；路由、诊断、接待、继续诊断、追问忙碌或状态不明时，任务保持 PENDING。空闲判断复用原有队列观察，不增加数据库轮询。已经开始的学习不取消、不重跑，随后到达的前台任务也不会等待学习结束；因此仍可能短暂并行，并不保证模型服务容量完全隔离。连续繁忙可能延后学习，待处理原文的 7 天期限保持不变。

已提炼的脱敏经验卡不按时间过期，报告和日志自然到期也不会清除经验。点赞、点踩和纠正替代仍按各自来源生效；主动删除来源会话会停用相关经验，并阻止晚到任务重新启用。升级前按旧策略清除的卡片无法恢复，也不会自动重新提炼。

每条回答最多保存 128 个不同请求 ID，反馈来源配额仍为 10,000 条；提炼任务的 10,000 条额度只计算 PENDING 和 RUNNING。已完成、失败或停用的历史经验不占提炼任务名额。反馈配额满返回 429；只有后台任务容量满时仍保存投票。待处理原文最多保留 7 天，任务成功或失败后清除私有上下文；文字反馈正文和核验工作区继续按各自原有期限清理，具体见[文字反馈接入说明](website-answer-feedback-upgrade.md)。仍可访问的来源继续保留幂等记录。

当前不做向量服务、经验合并、自动修改 Skill 或模型权重。将会话上下文与跨会话经验分开、在后台整理经验，参考了 [LangGraph 的记忆设计](https://docs.langchain.com/oss/python/concepts/memory)。这里针对故障定位增加了明确纠正目标和来源证据检查，实际效果以定位质量和耗时验证为准。

## 4. 部署和验收

经验卡长期保留、召回去重和活动任务额度调整只需升级小刀服务端。Web API、响应 schema、七个 MCP 工具和既有开关均不变，已接入的网站无需为这次调整修改请求；原文字反馈和管理员资料的 Web 适配要求继续保留。没有新增经验保留配置，也不新增仓库或版本字段。

`GENERIC_MEMORY_ENABLED=false` 为默认值，通用和专用 `direct` 的 V2 Markdown 报告仍可正常赞踩。网站验收应覆盖经验库开关两种状态、通用原问题超出提炼上限和任务容量已满，确认按钮与投票均正常；同时验证专用报告不触发通用经验提炼，以及登录、反馈归属、指定轮次、请求幂等、赞踩切换和删除。开启经验库前，再完成提炼失败、重启验证，并确认实际安装的通用 Skill 能读取经验参考。

真实模型验证先检查对应入口的 `--plan-only`，核对身份、调用数、预算和阻塞项。使用同一组典型问题比较启用前后的正确性、排查步骤、时延和模型消耗；确定性测试通过本身不能证明诊断质量提高。

完成经验库验收后再启用。关闭期间不创建或积压新的提炼任务，也不召回经验，已有评价仍可读取、提交和换票，经验卡继续保留；原始材料和核验工作区仍按各自期限清理。重新开启不会自动补提炼旧投票；用户用新请求再次点赞时，满足条件且从未提炼的通用报告或普通追问才会创建任务；纠正答案仍须满足证据核对条件。脱敏依赖模型抽象，格式和敏感信息检查无法识别所有私有名称；启用前须用典型数据核查脱敏结果。正式 Test Flow 的 affected 与 full deterministic 结论以对应源码快照的 `verdict.json` 为准。
