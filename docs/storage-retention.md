# 服务端文件保留与清理

Web 会话正文、报告及历史问答永久保存，用户主动删除时再清除。日志等大文件默认保留 **15 天**，磁盘紧张时可提前回收已完成轮次的文件。服务启动时及每小时扫描到期资源，每 60 秒检查磁盘余量和可提前释放的工作区。停机期间不清理，恢复服务后继续处理。

## 配置保留期限

在 Linux 服务端实际加载的 `.env` 中设置 `WEB_RESOURCE_RETENTION_DAYS=15`，然后重启服务。该配置控制 Web 日志资源和闲置等待期限，不控制正文。`HISTORY_RETENTION_DAYS=30` 继续控制非 Web 历史、创建请求幂等记录及删除凭据。两项均只接受 1–3650 的整数，进程环境变量优先于 `.env`。

每天按 24 小时计算。Web 日志从各轮完成时间起计时；仍在执行的任务延后回收。下表使用默认配置。

重启后，仍未清理的旧记录也按新期限计算，原来的完成时间或业务活动时间不会重置。升级时会从有效消息、助手提问及上传完成事件补齐旧轮次的业务活动时间；没有可靠事件的记录采用首次升级时间，并持久保存，后续重启不再延长。已删除的内容无法恢复；缩短期限可能使旧记录在启动清理时立即到期。已进入持久化删除清单的任务会继续完成。

升级保护尚未进入删除流程的 Web 历史。每轮清理前将公开报告和正式报告原始字节独立归档到数据库，校验失败则保留原文件。不会自动撤销旧删除任务或恢复已删除正文。

## 各类数据的策略

| 数据 | 保留与清理方式 |
| --- | --- |
| Web 消息、助手提问与回复、报告、历史追问及回答 | 永久保存。正式报告的下载地址、原始字节和哈希保持不变。 |
| Web 附件名称、大小、哈希及清理状态 | 永久保存；元数据不等于文件仍可下载或复用。 |
| Web 原始附件、证据、附件副本、ZIP、Job 执行记录和追问日志快照 | 各轮完成后保留 15 天；磁盘紧张时可提前清理已结束轮次。使用中的资源延后处理。 |
| Web 等待输入或附件的闲置轮次 | 连续 15 天没有业务活动后结束旧轮，正文保留；同一会话可新开一轮。磁盘紧张不会提前取消等待中的轮次。 |
| 网站预约上传但未被有效轮次引用的附件 | 预约满 15 天后回收；共享原文件须等最后一个仍需使用它的轮次释放。 |
| 非 Web 历史诊断、报告及附件 | 按 `HISTORY_RETENTION_DAYS`，默认 30 天。 |
| 成功任务的普通、Logparse 和追问工作区 | ZIP、追问快照等依赖均完成后尽快释放；不把中间副本留满 15 天。 |
| 上传临时文件、提案暂存、失败或中断工作区、状态写入临时文件 | 超过 24 小时且没有活跃使用者时清理。 |
| 无主资源、Job 目录 | 超过 7 天且没有状态引用时清理；受控布局内的空父目录也会回收。 |
| 删除失败后的隔离目录与清理清单 | 作为待处理任务保留，后续重试；成功后删除清单。失败会写入服务日志，不能按成功处理。 |
| 网站创建请求的幂等记录 | 创建后保留 30 天，过期后释放；已有会话正文不受影响。过期附件请求不可复活文件，重新上传需新请求 ID。 |
| 已删除会话的最小删除凭据 | 从删除请求受理时保留 30 天，且须等文件清理完成后才清除相应索引和清理记录。 |
| Web 内部进度、状态同步事件 | 已结束轮次按 `HISTORY_RETENTION_DAYS` 清理；组成可见历史的消息、提问、回答和结果事件继续保留。 |
| 经验提炼源文本、提炼任务和经验卡片 | 待处理源文本仍最多保留 7 天，文字反馈正文和核验工作区沿用原清理期限；经验卡不按时间过期。赞踩、纠正替代和主动删除来源的规则不变；历史赞踩及幂等回执保留，已清理资源的记录不再占源配额。10,000 条任务额度只计算 PENDING/RUNNING，已完成、失败或停用的历史经验不占任务名额。 |
| PostgreSQL 数据库 | 永久正文和报告持续积累；删除的数据由 autovacuum 回收并复用，不在业务事务中执行 `VACUUM FULL`。数据库磁盘、备份和 WAL 容量由部署方监控。 |
| DFX 与 Journey 日志 | 每个文件最多 16 MiB，最多 4 份备份；每类合计最多 80 MiB。单条事件最多 64 KiB，超限时保留关联标识并明确标记裁剪。 |
| 服务启动时固定的 Skill、内置资源副本 | 每个 `DATA_ROOT` 仅使用一个 `tmp/assets` 目录；正常关闭后清理，异常退出的残留在下次取得实例锁后清理。 |
| 网站示例代理的下载临时文件 | 请求结束立即清理，下载总时限 30 分钟；启动及每 10 分钟扫描，回收超过 1 小时且确认不再使用的目录。 |

终态轮次按完成时间计时，旧数据没有完成时间时采用该轮自己的最后更新时间。闲置任务按最后业务活动计时。重命名会话、读取报告、刷新页面和新开下一轮都不续期旧轮次。

经验卡长期保留只需升级服务端，不改变 Web API、响应 schema 或 MCP 工具。完全相同的经验内容只在召回时去重，不合并来源和投票；已按旧策略清除的卡片无法恢复，也不会自动重新提炼。`GENERIC_MEMORY_ENABLED` 仍默认关闭，不新增保留期限配置。

保留期限不是整个服务的硬性磁盘配额。单附件最多 2.5 GiB，每个 Case 最多预约 20 个附件，正式资源总量最多 5 GiB；同一预约请求的重试不占新名额。网站每轮最多 200 条消息，每个会话同时占用额度的附件最多 20 个；文件物理清理完成后释放额度，永久元数据不占名额。容量规划还要考虑所配置保留期内的并发量、临时副本和数据库回收所需空间。执行器仍使用原有任务时限和输出限制。

## 磁盘紧张时的处理

| 配置 | 默认值 |
| --- | --- |
| `RESOURCE_DISK_LOW_FREE_BYTES` | 10737418240（10 GiB） |
| `RESOURCE_DISK_LOW_FREE_PERCENT` | 10 |
| `RESOURCE_DISK_TARGET_FREE_BYTES` | 21474836480（20 GiB） |
| `RESOURCE_DISK_TARGET_FREE_PERCENT` | 15 |

空闲空间低于两个触发值中的较大值时开始回收，达到两个目标值中的较大值后停止。字节值接受非负整数，比例接受 0–99 的整数；目标字节值和比例须分别大于触发值。小磁盘部署应相应调低字节阈值，否则即使磁盘尚未写满，也会拒绝新的大文件写入。

先重试未完成删除、释放无用副本和到期资源，再按完成时间从旧到新回收已结束的 Web 轮次。每轮删除后重新测量真实空闲空间；隔离目录移动、失败删除和共享文件不能重复计作释放收益。报告归档失败或仍有任务使用时跳过，无安全候选则停止回收。

主要大文件写入使用同一个进程内容量预约，避免并发上传同时占用相同余量。文件预约记录本身不预占磁盘，实际上传开始时才预约。容量不足会唤醒清理，Web 上传返回可重试的 `503 / AGENT_STORAGE_PRESSURE`。准入检查不是全盘硬配额；外部 Logparse 仍受原阶段输出上限约束，外部进程挤占空间时仍可能发生写入失败。单份追问日志快照 1 GiB、总量默认 5 GiB 的限制也保持不变。

## 并发和失败处理

清理前会复查归属、状态和使用中的资源。上传、下载、诊断与归档尚未结束时跳过，后续扫描再试。清理只作用于服务拥有的具体路径，不沿符号链接访问其他目录，也不删除其他会话的数据。

需要跨数据库和文件系统删除的数据，先持久保存清理清单，再移除引用和隔离文件。进程在中途退出后，可根据清单继续处理。某项删除失败不能阻止其他候选长期被清理；临时文件清理与历史清理也独立执行。

日志轮转后，Journey 渲染器会读取全部保留分段。早期事件已淘汰时会明确说明仅有保留片段，不能把裁剪后的事件当作完整测试证据。

数据库回收在后台执行，不放在用户请求里；`VACUUM` 期间数据库操作需要等待，并需要额外磁盘空间。若旧 Journey 文件只有一条超过文件上限的记录，无法恢复事件序号，服务会保留明确的截断标记并拒绝无依据地接续序号；部署方需为后续运行选择新的 Journey 日志文件。

## 网站接入的变化

页面应提示“会话正文和报告长期保存；日志通常保留 15 天，空间不足时可能提前清理”。清理后该轮的 `resources_expired=true`，显示“相关日志已清理，本轮仅供查看”。报告和已有问答仍可查看，原报告文件仍可下载；ZIP 不再提供链接，旧文件地址返回 `410 / AGENT_RESOURCE_EXPIRED`。该轮不再接受新追问，同一会话可新开一轮。部署调整期限时，页面提示也须同步更新。

清理状态属于轮次：`resources_expired_at` 记录时间，`resource_cleanup_reason` 为 `RETENTION_EXPIRED` 或 `DISK_PRESSURE`。附件最后一个有效使用者释放后才变为 `EXPIRED`，因此不能用附件的全局状态代替轮次只读状态。

SSE 游标落在已清理的历史范围时，接口返回 `409 / AGENT_EVENT_CURSOR_EXPIRED`。客户端先读取会话当前快照，再用快照中的 `last_event_id` 作为 `Last-Event-ID` 重新订阅。不要无限重试同一个过期游标，也不要把事件序号缺口当成完整回放。普通 `EventSource` 不能设置这个请求头，长期会话应使用支持该流程的流式 `fetch`。

幂等保证仅适用于保留期内。过期请求不得作为自动重试依据；超出保留期需要用户重新发起。删除凭据过期后，重复 DELETE 可能返回 404。新的诊断始终使用新的请求 ID。

## 部署边界

这些策略负责小刀在线服务和仓库自带网站代理创建的运行文件，不管理 codeagent 自身的会话、记忆或缓存。Skill 源目录、Logparse 安装目录和部署配置不是运行历史，不参与清理。

不要把标准输出长期重定向到没有轮转的文件。使用 journald、容器日志或反向代理日志时，部署方必须同时配置容量上限和保留期限；小刀无法删除这些外部进程拥有的日志。

旧版本留在系统临时目录中的 `problem-locator-assets-*` 或没有归属清单的 `xiaodao-website-*` 不会被凭名称删除。升级时须先停止对应旧服务、确认目录归属，再清理这些旧残留。新版本使用上述受控生命周期。

旧 Case 快照若已损坏，无法校验完成时间或资源归属，会跳过自动到期处理。升级核查时须修复记录，或确认归属后清理，不能把这类历史残留视为已纳入自动回收。

用户显式导出的报告、离线迁移副本以及 Test Flow 证据不属于在线清理目录。Test Flow 证据继续遵守仓库要求：先用 `evidence.mjs report` 或 prune dry-run 查看，再按精确 run ID 人工删除；被 verdict 引用的源码收据不得删除。
